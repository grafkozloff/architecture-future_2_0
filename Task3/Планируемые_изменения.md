## Обоснование планируемых изменений

### Q1 2026: Фундамент и безопасность

| **Этап**                                                                   | **Бизнес-обоснование**                                                                                                                      | **Влияние на бизнес-показатели**                                                                                                                |
|----------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------|
| Определение доменов и границ (Архитектура)                                 | Чёткое разделение ответственности между командами. Позволяет параллельно развивать медицинские, финансовые и ИИ-направления без блокировок. | Скорость выхода на рынок: ускорение разработки за счёт независимости команд. Снижение затрат: уменьшение координационных издержек.              |
| Стандартизация data-контрактов (Архитектура)                               | Установление чётких форматов и SLA для обмена данными между доменами.                                                                       | Качество сервиса: гарантия актуальности и точности данных в отчётах. Снижение затрат: уменьшение количества ошибок и переделок.                 |
| Выбор облачного провайдера (Команда платформы данных)                      | Размещение инфраструктуры в облаке с гибкой моделью оплаты вместо дорогостоящих ЦОД.                                                        | Снижение затрат: сокращение CAPEX, переход на OPEX модель. Масштабирование: возможность мгновенного увеличения мощностей при пиковых нагрузках. |
| Развертывание DataHub, Dremio, Kafka, IAM (Команда платформы данных)       | Создание единой платформы данных для управления data-продуктами и обеспечения безопасного доступа.                                          | Качество сервиса: централизованный контроль качества данных. Безопасность: единая система аутентификации для всех сервисов.                     |
| Классификация данных (PII, PHI и т.д.) (Команда безопасности и комплаенса) | Обязательное требование для работы с медицинскими и финансовыми данными. Предотвращает риски утечек.                                        | Регуляторная безопасность: снижение риска штрафов до нуля. Репутация: защита доверия клиентов.                                                  |
| Интеграция с платформой данных (все домены)                                | Начало перехода от монолитного DWH к распределённой архитектуре.                                                                            | Скорость принятия решений: первый шаг к быстрой аналитике. Снижение затрат: начало сокращения нагрузки на legacy-системы.                       |
| Проектирование портала самообслуживания (Команда домена аналитики)         | Создание инструмента для бизнес-пользователей, снижающего зависимость от IT-отдела.                                                         | Скорость принятия решений: будущее сокращение времени получения отчётов с часов до минут.                                                       |

### Q2 2026: Пилотная миграция и стандартизация

| **Этап**                                                           | **Бизнес-обоснование**                                                                                         | **Влияние на бизнес-показатели**                                                                                                   |
|--------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------|
| Создание реестра data-продуктов (Архитектура)                      | Единый каталог всех доступных данных для аналитики. Упрощает поиск и устраняет дублирование.                   | Скорость принятия решений: аналитики находят нужные данные за минуты вместо дней.                                                  |
| Создание data-продуктов (ФинТех, Медицинские и ИИ сервисы)         | Упаковка данных в готовые к использованию форматы для аналитики.                                               | Скорость выхода на рынок: новые продукты могут использовать готовые data-продукты вместо создания с нуля.                          |
| Реализация API для медицинских сервисов (ФинТех сервисы)           | Позволяет ФинТех сервисам предлагать новые услуги на основе медицинских данных (например, страховые продукты). | Качество сервиса: персонализированные финансовые предложения для клиентов клиник. Новые доходы: кросс-продажи между направлениями. |
| Интеграция с ИИ сервисами (Медицинские сервисы)                    | Врачи получают инструменты ИИ-диагностики напрямую в рабочих процессах.                                        | Качество сервиса: повышение точности диагнозов. Конкурентное преимущество: передовые технологии в клиниках.                        |
| Разработка MVP портала самообслуживания (Команда домена аналитики) | Первая версия инструмента для бизнес-аналитиков.                                                               | Проверка архитектуры и технических решений. Ускорение получения отчетов для первых пользователей.                                  |
