### **Сетевые настройки**

**NAT Gateway:**
*   **Причина использования:** Безопасность через security by design
*   **Преимущества:**
    *   ВМ без публичных IP защищены от прямых атак из интернета
    *   Возможность обновления пакетов и доступа к внешним ресурсам
    *   Соответствие требованиям для изоляции конфиденциальных данных

**Security Groups:**
*   **External SG:** Ограниченный набор портов (22, 80, 443)
*   **Internal SG:** Полный доступ внутри подсети для сервисной коммуникации
*   **Причина разделения:** Принцип минимальных привилегий, сегментация сети

**Subnet /24 (254 хоста):**
*   Достаточно для текущих нужд (9 ВМ + сервисы)
*   Возможность масштабирования до 250+ ресурсов
*   Простота управления и документирования

### **Управляемые сервисы**

**Managed Kafka:**
*   **Преимущества:** Автоматическое масштабирование, встроенная отказоустойчивость, мониторинг
*   **3 брокер****а****:** Обеспечение отказоустойчивости (N+2 для production)

**Managed PostgreSQL:**
*   **Причина выбора:** Автоматические бэкапы, пачтинг, репликация
*   **Версия 15:** LTS версия с длительной поддержкой

**S3 Storage:**
*   **Бесконечная масштабируемость** для данных аналитики
*   **Экономичность** для хранения холодных данных
*   **Интеграция** с Dremio для прямых запросов

## **2. Infrastructure as Code (IaC)**

### **Почему декларативный подход?**

1.  **Идемпотентность:** Одно и то же определение конфигурации всегда дает одинаковый результат
2.  **Повторяемость:** Инфраструктура может быть воссоздана в любой момент
3.  **Документирование:** Код является живой документацией состояния инфраструктуры
4.  **Контроль версий:** Возможность отслеживать изменения и откатываться при необходимости

### **Преимущества для "Будущее 2.0":**

#### **Воспроизводимость:**

*   **Окружения-клоны:** Dev/Stage/Prod окружения создаются одинаково
*   **Аварийное восстановление:** Инфраструктура может быть восстановлена за минуты
*   **Тестирование:** Можно создавать временные среды для тестирования новых версий

#### **Масштабируемость:**

*   **Горизонтальное масштабирование:** Добавление новых инстансов через изменение count
*   **Региональное развертывание:** Копирование конфигурации в другие регионы
*   **Модульность:** Переиспользование компонентов для новых доменов
